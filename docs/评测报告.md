# 评测报告:主动澄清对冷启动对话式推荐的价值(v2 优化后)

> 项目:LLM4Rec 对话式推荐智能体
> 日期:2026-08-18(优化后)　|　评测脚本:`scripts/eval_simulator.py`
> 数据:500 款商品库(DeepSeek 生成 + 人工校验,已入库 MySQL)

---

## 1. 评测设计

**研究问题**:在冷启动场景(用户无历史行为数据)下,系统通过"主动澄清对话"补足信息,能否比不澄清/传统热门榜更准地命中用户想要的东西?

**方法:LLM 用户模拟器**(对话式推荐 CRS 的标准评测做法)

- 从商品库随机抽取 **30 个目标商品**作为模拟用户的"心仪之选"
- **3 个随机种子(42/7/123)各跑 30 人**,报告均值±标准差,保证结论稳定
- DeepSeek 扮演该用户与系统**真实多轮对话**:首句只说品类(冷启动),系统澄清补齐用途/预算/配置
- 用户不知道"目标商品 id",只凭需求判断;命中由程序判定(推荐卡片是否含目标商品)
- 三组对比:

| 组别 | 说明 |
|---|---|
| **A 有澄清** | 系统主动追问品类/用途/预算/配置再推荐 |
| **B 无澄清** | 同一用户,系统不追问,基于首句直接推荐 |
| **C 热门榜** | 传统推荐:按销量排序 Top-3,无对话 |

**指标**:Success@3(Top-3 命中目标占比)、平均轮次、平均澄清次数

---

## 2. 评测结果(优化后)

| 组别 | Success@3(均值±std) | 平均轮次 | 平均澄清次数 |
|---|---|---|---|
| **A 有澄清** | **0.389 ± 0.016** | 5.23 | 2.13 |
| **B 无澄清** | 0.344 ± 0.016 | 4.77 | 0.0 |
| **C 热门榜** | 0.011 ± 0.016 | 1.0 | 0.0 |

### 核心结论

1. **对话式推荐碾压传统热门榜**:冷启动场景热门榜命中率仅 **1.1%**(500 款里盲猜几乎不可能命中),对话式推荐 **38.9%,是其约 35 倍**。
2. **主动澄清有正向增量**:有澄清比无澄清命中率高 **13%**(0.389 vs 0.344),且 3 个 seed 结论一致(±0.016,稳定)。
3. **澄清高效**:平均 **2.13 次**追问即收敛,追问链(品类→用途→预算→配置)信息增益有效。

## 3. 优化前后对比

| 指标 | 优化前(单seed 42) | 优化后(3seed 均值) | 变化 |
|---|---|---|---|
| A 有澄清 Success@3 | 0.30 | 0.389 | **+30%** |
| B 无澄清 Success@3 | 0.20 | 0.344 | +72% |
| C 热门榜 Success@3 | 0.00 | 0.011 | 约0 |

**优化要点**(本阶段完成的体验/功能修复):
- **品类入槽位**:修复"用户说买手机、系统推笔记本"的致命 bug(A 组 +30% 的主因)
- 澄清链智能化(品类→用途→预算→配置 四问,不再跳过关键信息)
- 复合意图(一句话多个意图,反事实后追加追问缺失信息)
- 反事实解释引用具体数字对比(Top-3 vs 目标商品)
- 召回增强(槽位结构化 query、候选放宽)+ 评审 Agent(理由一致性/硬约束兜底/多样性)
- 内容 ItemCF 相似商品 + text2sql 真 MySQL 查询(工具调用落点)

## 4. 一个命中案例(说明澄清如何工作)

```
用户: 我想买个手机,日常用,预算4500左右
系统: 想先了解下你的使用场景:主要是日常办公、写代码/编程,还是玩游戏或看视频?
用户: 日常用,不打游戏,内存至少12G
系统: [推荐 3 款手机]  ← 品类正确
用户: 重量别太重就行
系统: 好的,按新的重量要求重新筛选 → [iQOO Neo / 三星Galaxy / 华为Pura] ← 收敛
```

关键:① 品类从首句正确提取(不再推错品类)② "不打游戏"不会被误当成用途 ③ 每轮反馈实时改变下一轮结果。

## 5. 结论与局限(诚实声明)

### 结论
对话式推荐通过主动澄清,在冷启动场景下**显著优于**传统热门榜(35 倍),且澄清比不澄清再提升 13%,多次运行结论稳定。这验证了项目核心假设:**用对话交互可以补足缺失的行为信号**。

### 局限(答辩主动声明)
1. **Success@3 绝对值 38.9% 不算极高**:目标是从 500 款中抽取的特定商品,Top-3 命中特定款本就困难;模拟器需求与商品属性存在偏差。对比的意义在于 A > B ≫ C 的趋势,而非绝对数值。
2. **数据与评测均为 LLM 参与**:商品数据由 DeepSeek 生成、用户由 DeepSeek 模拟,存在"生成-评估"同源偏差。对策:①商品数据人工抽查 ②命中判定程序化 ③3 seed 结论一致。
3. **A vs B 差距(13%)小于预期**:原因是品类修复让"无澄清"组也大幅提升(首句带品类即可筛对)。这反而说明品类是基础信号,澄清的价值体现在更深层的用途/配置信息上。
4. **平均轮次 5.23 偏高**:澄清链 4 问 + 模拟器多轮试探所致。真实用户通常 2-3 轮即可,是评测设定偏严格。
